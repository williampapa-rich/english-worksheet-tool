# Extractor Fixture 자료

추출 파이프라인 (`packages/extractor/`) 의 개발 / 테스트용 입력 자료.
**일부 자료는 출력 결과물의 reference 로도 사용됨** — 아래 §"자료 종류" 참고.

## 디렉토리 구조

```
admin/fixtures/extractor/
├── pdf/
│   ├── text-layer/   # 텍스트 레이어 있는 PDF (PyMuPDF 1차 경로)
│   │   ├── 변형문제/   # ← Phase 3 출력 reference (아잉카 변형문제집, hwp/pdf 페어)
│   │   └── 상세분석/   # ← Phase 1 출력 reference (아잉카 구문분석집, hwp/pdf 페어)
│   └── scanned/      # 스캔본 PDF (Vision fallback 경로, 예: 학교 내신지)
├── image/            # 단일 이미지 (핸드폰 촬영 / 스크린샷)
└── text/             # .txt 직접 입력
```

## 자료 종류 — 실유저 입력 vs 출력 reference

이 fixture 디렉토리는 **두 가지 용도**가 섞여 있다. 사용 시 혼동 주의.

### 1. 실유저 입력 simulation — 추출 파이프라인의 *입력*

PM-6 (ADR-0003 §"PM 결정 (확정)") 의 운영 가정:

- **실유저 (와이프, 강사) 입력의 default = 영어만 / 또는 문제만** (한글 해석 없음).
- 평가원 / EBSi / 학교 내신 / 사용자 자체 자료가 여기 해당.

추출 파이프라인 (P0-3 / P0-4 / P0-5) 의 단위 테스트 입력으로 사용.

### 2. 아잉카 출력 reference — 시스템이 *생성해야 할 결과물*의 형태

`pdf/text-layer/변형문제/` 와 `pdf/text-layer/상세분석/` 은 **아잉카가 모의고사 지문을 사용해 만든 자료**. 같은 모의고사 지문에 대해 hwp / pdf 두 버전이 페어로 들어있다.

- **변형문제 (`변형문제/`)**: 모의고사 원지문을 사용해 유형 변경 / 어휘 교체 / 어순 변경 등으로 변형한 문제집. **Phase 3 (변형문제 생성) 의 출력 reference**.
  - 학생용 / 교사용으로 분리된 케이스도 있음 (28건).
  - 학년: 1학년 38건 / 2학년 87건 / 3학년 32건. 연도: 2017 ~ 2026.
- **상세분석 (`상세분석/`)**: 모의고사 지문을 구문 분석한 자료 (상단 라벨 / 하단 라벨 / 괄호 / 화살표 등). **Phase 1 (구문분석 에디터) 의 출력 reference** — 에디터로 만들 결과물의 형태.
  - 분권 패턴: `_18_30_` (앞 부분) / `_31_42_` 또는 `_31_45_` (뒷 부분).

이 두 폴더는 **추출 파이프라인의 입력으로도 사용 가능** — 한글 해석/어휘/구문분석이 함께 있는 *풀세트* 자료라 PM-5 (옵션 B 추출 — 자료에 보이는 것 추출) 의 검증에 적합.

### 두 용도의 분류

| 폴더 | 용도 | 풀세트? | Phase |
|---|---|---|---|
| `pdf/text-layer/변형문제/` | (1) 추출 입력 / (2) Phase 3 출력 reference | 풀세트 (변형문제 + 정답 + 해설) | Phase 0 추출 / Phase 3 생성 |
| `pdf/text-layer/상세분석/` | (1) 추출 입력 / (2) Phase 1 출력 reference | 풀세트 (구문분석 마크업 포함) | Phase 0 추출 / Phase 1 에디터 |
| `pdf/text-layer/` 직속 자료 (있다면) | 추출 입력만 | 다양 | Phase 0 |
| `pdf/scanned/` | 추출 입력만 | 영어만 (스캔본 default) | Phase 0 |
| `image/` | 추출 입력만 | 영어만 default | Phase 0 |
| `text/` | 추출 입력만 | 다양 | Phase 0 |

## hwp 파일에 대한 정책

- 본 도구는 **HWP 직접 파싱하지 않는다** (CLAUDE.md §1.4 비-목표).
- hwp 페어는 **사람의 reference / 재출력 검증용**: PM 또는 와이프가 한컴오피스로 열어서 "우리 도구의 출력이 이만큼 나와야 한다" 의 시각적 비교 기준.
- 추출 파이프라인은 같은 자료의 **pdf 만 입력**으로 사용. hwp 는 무시.

## 파일명 컨벤션

아잉카 자료 (현재 보유) 의 패턴:

```
모의고사_<학년>_<연도>_<월>_<자료종류>_<문항범위>_<문제수>문제_[학생용|교사용_]아잉카[아카데미].<확장자>

예) 모의고사_2학년_2024년_09월_변형문제_18_42_189문제_아잉카.pdf
    모의고사_1학년_2017년_03월_상세분석_18_30_아잉카.hwp
```

신규 자료 추가 시 위 패턴 따름. 비-아잉카 자료는 출처 명시:

```
<출처>_<학년>_<연도-월>[_<부가식별>].<확장자>
예) evaluator_suneung_2024-11.pdf
    school_gangnam-high_2024-mid1.pdf
```

## Git 추적 정책

본 디렉토리 하위는 **git 무시** (`.gitignore` §"Extractor fixture 자료").

- 아잉카 자료 = 유료 멤버십 자료
- 학교 내신지 = 비공개
- 평가원 / EBSi 자료도 재배포 회색지대
- `.DS_Store` 도 자동 무시 (`admin/fixtures/extractor/**/*` 패턴에 흡수)

폴더 구조 (`.gitkeep`) 와 본 README 만 추적됨.

코드와 함께 자료를 공유해야 할 경우 (CI 통합 테스트 등) 는 별도 인벤토리 매니페스트
파일 (`fixtures-manifest.json`) 로 메타만 커밋하고 자료 자체는 별 저장소 / S3 등에서
가져오는 방식 검토. Phase 0 단계에서는 로컬 자료만 사용.

## 누가 이걸 쓰는가

- `packages/extractor/` 의 단위 / 통합 테스트 (P0-3 / P0-4 / P0-5)
- `packages/extractor/` 의 수동 검증 스크립트
- **Phase 1 진입 시**: 상세분석 자료를 Tiptap 에디터의 출력 형태 reference 로 검토
- **Phase 3 진입 시**: 변형문제 자료를 변형 생성 LLM 의 출력 reference 로 검토
- `admin/eval/` 의 LLM 출력 평가 (Phase 3+)
