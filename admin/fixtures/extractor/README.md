# Extractor Fixture 자료

추출 파이프라인 (`packages/extractor/`) 의 개발 / 테스트용 입력 자료.

## 디렉토리 구조

```
admin/fixtures/extractor/
├── pdf/
│   ├── text-layer/   # 텍스트 레이어 있는 PDF (예: 아잉카 자료)
│   └── scanned/      # 스캔본 PDF (예: 학교 내신지)
├── image/            # 단일 이미지 (사진 / 스크린샷)
└── text/             # 직접 입력 텍스트 .txt
```

## 자료 구성 가이드

PM-6 (ADR-0003 §"PM 결정 (확정)") 의 운영 가정:

- **아잉카 자료** = 학습용 / 개발용. 영어 + 한글 해석 + 어휘 풀세트.
- **실유저 입력 (와이프, 강사)** = 영어만 / 또는 문제만 (한글 해석 없음).

따라서 fixture set 에는 **양쪽 분포 모두** 포함되어야 한다:

| 카테고리 | 풀세트 (해석 + 어휘 포함) | 영어만 / 문제만 |
|---|---|---|
| `pdf/text-layer/` | 아잉카 자료 1건 | 평가원 / EBSi / 사용자 자체 자료 1건 |
| `pdf/scanned/` | (선택) | 학교 내신지 스캔본 1건 |
| `image/` | (선택) | 핸드폰 촬영 노트 / 시험지 1건 |
| `text/` | 한글 해석 같이 붙인 텍스트 1건 | 영어 본문만 1건 |

## Git 추적 정책

본 디렉토리 하위는 **git 무시** (`.gitignore` 참고). 사유:

- 아잉카 자료 = 유료 멤버십 자료
- 학교 내신지 = 비공개
- 평가원 / EBSi 자료도 재배포 회색지대

코드와 함께 자료를 공유해야 할 경우 (CI 통합 테스트 등) 는 별도 인벤토리 매뉴페스트
파일 (`fixtures-manifest.json`) 로 메타만 커밋하고 자료 자체는 별 저장소 / S3 등에서
가져오는 방식 검토. Phase 0 단계에서는 로컬 자료만 사용.
